BGP and EVPN membership can stay up while VXLAN forwarding fails. This PR adds an optional `evpn_monitoring` timer that pings a configured overlay IP across one stretch every 30s. It writes success and RTT through node-exporter's textfile collector, which this PR enables in the bootc image (`image/rhel10/node-exporter.service`) and in the non-bootc container.

- **Alerts.**
  - `EGAEvpnPathProbeFailed` fires after 5m of failed fresh probes.
  - `EGAEvpnPathProbeUnavailable` fires after 5m of stale, unreadable or vanished results.
  - A local ping error leaves the result stale instead of reporting loss.
  - Both alerts have runbook sections in `monitoring/runbooks.md`, and the appliance dashboard shows fresh RTT.
- **The role.**
  - The target must be an IP address, and the probe unit is sandboxed.
  - The role waits until node-exporter exports a result for the configured target. So it fails on an image whose node-exporter does not read the textfile directory, or when the probe cannot run against that target.
- **Removal.**
  - Clearing the target, turning off node_exporter or running `teardown.yml` removes the probe.
  - It leaves a marker that keeps the unavailable alert quiet. The marker carries the SELinux type node-exporter's container can read.
- **Checks.**
  - `check_dashboards.py` scopes `ega_path_probe_*` selectors, with a test.
  - A new `check-unit` target runs a unit test of the probe script with a fake `ping` and `promtool check metrics`; `ci-source.md` records it.
- **e2e.** It probes the first stretch, then drops VXLAN packets with nft while BGP and the remote VTEP stay up, and checks failure and then recovery. Finally it clears the target and checks that the probe is removed.
